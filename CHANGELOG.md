# Журнал изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии по SemVer.
Каждое изменение попадает сюда и в затронутые файлы `docs/`.

## [2.9.1] — 2026-11-10

### Голос
- Opus: **fullband**, constrained VBR, LSB depth 16 — чище высокие частоты.
- **Восстановление потерянных пакетов (FEC)**: при пропуске 1–2 пакетов
  предыдущий кадр восстанавливается из FEC-данных следующего, меньше «провалов»
  и щелчков при джиттере.
- Джиттер-буфер: накопление 3 пакетов перед воспроизведением и сброс
  переполнения.
## [2.9.0] — 2026-11-09

### Качество звука
- **Шумоподавление (гейт)**: тихий фоновый шум и гул приглушаются с плавным
  открытием/закрытием, без щелчков.
- **Автогромкость (AGC)**: тихая речь подтягивается к комфортному уровню,
  громкая — ограничивается.
- **High-pass 80 Гц**: убирает низкочастотный гул.
- Оба эффекта настраиваются: Настройки → Голос → «Шумоподавление» и
  «Автогромкость» (по умолчанию включены).
- DSP применяется до Opus; есть юнит-тесты `tst_audio_dsp`.
## [2.8.6] — 2026-11-09

### Голос
- **Сторож микрофона**: если в разговоре устройство перестаёт отдавать данные,
  захват перезапускается автоматически; в лог пишется предупреждение.
- Телеметрия раз в 5 секунд: `VOICE: захват=… Б, воспроизведено=… Б,
  readyRead=…, отправлено=…, получено=…`.
- Логируются изменения состояния микрофона и динамиков.
## [2.8.5] — 2026-11-09

### Голос
- Переключатель **«Шифрование голоса (E2EE)»** в настройках: можно выключить
  для диагностики — звонок пойдёт на ключе комнаты.
- В лог добавлены состояние и ошибки микрофона/динамиков сразу после старта.
## [2.8.4] — 2026-11-09

### Голос
- **Согласование аудиоформатов**: микрофон и динамики открываются в ближайшем
  поддерживаемом формате, PCM ресемплится в 48 кГц моно для Opus и обратно.
  Раньше при неподдерживаемом формате звук мог пропадать или хрипеть.
- Джиттер-буфер: накопление 3 пакетов перед воспроизведением и сброс лишних
  (меньше щелчков и «бульканья»).
- В лог пишутся форматы устройств и счётчики: `VOICE: отправлено пакетов=…,
  получено=…`.
## [2.8.3] — 2026-11-09

### Голос
- **Профили качества звука** в настройках: Речь 96 кбит/с, Музыка 128 кбит/с,
  Максимум 192 кбит/с. Битрейт применяется при следующем звонке.
## [2.8.2] — 2026-11-09

### Голос
- Расшифровка пакетов с **fallback на ключ комнаты**: если одна сторона уже
  перешла на парный E2EE-ключ, а вторая ещё нет, звук не пропадает.
- Диагностика в логе: `VOICE: вход в E2EE`, `VOICE: получен ключ участника`,
  `VOICE: не удалось расшифровать пакет`, `VOICE: нет устройства ввода`.
## [2.8.1] — 2026-11-09

### Исправлено
- **Звонки в обе стороны**: принимающая сторона теперь отправляет
  `voice.accept`, и звонящий получает `ev.voice.accepted` (раньше он оставался
  в состоянии «Вызов…»).
- **Повторный звонок после завершения**: при выходе из комнаты сервер
  рассылает `ev.voice {joined:false}`, клиент сбрасывает состояние — новый
  вызов больше не отклоняется как «занято».
- Отмена вызова освобождает аудио и UDP.

### Голос
- Opus: 96 кбит/с, VBR, complexity 10, in-band FEC 10%, без DTX.
## [2.8.0] — 2026-11-09

### Сервер
- **Ограничение частоты запросов** на сессию: token bucket (60/с, burst 300),
  ошибка `RATE_LIMITED`.
- **Healthcheck и метрики** по HTTP: `--http-port`, `/healthz` и `/metrics`
  (`didog_connections`, `didog_uptime_seconds`).
## [2.7.0] — 2026-11-09

### Безопасность
- **E2EE групповых звонков**: sender keys — каждый участник рассылает свой
  медиаключ попарно (`voice.senderkey` / `ev.voice_senderkey`), сервер
  ретранслирует непрозрачные блобы. Исходящие пакеты шифруются sender key,
  входящие — ключом отправителя. До получения ключа — fallback на ключ комнаты.
## [2.6.0] — 2026-11-09

### Безопасность
- **E2EE голоса для личных звонков**: эфемерные X25519-ключи, обмен публичными
  ключами через сервер (`voice.pubkey` / `ev.voice_pubkey`), ключ медиа —
  `HKDF-SHA256`, AES-256-GCM. Сервер ключ не знает.
- Групповые звонки пока используют ключ комнаты (задокументированный fallback).
## [2.5.0] — 2026-11-09

### Новое
- **Отдельный клиентский установщик** `DiDog-Client-Setup-*.exe`: без
  `MessengerServer.exe` и серверного ключа — обновление клиента больше не
  конфликтует со службой сервера. Полный `DiDog-Setup-*.exe` остаётся для тех,
  кому нужен локальный сервер.
- **Серверный пакет** `DiDog-Server-*.zip` (`scripts/package-server.ps1`):
  сервер, TLS, зависимости Qt и `SERVER-README.txt`.
- **Крэш-дампы**: необработанные исключения пишутся в `<data>/crashes`
  (`crash-*.dmp` + `.txt` с кодом и адресом) — падения можно разбирать по стеку.
- **Звук уведомлений**: системный звук при новом сообщении и переключатель
  «Звук уведомлений» в настройках.
## [2.4.1] — 2026-11-09

### Исправлено
- **Клиент падал при наведении/фокусе на кнопках** (SIGSEGV в `ButtonFx`):

## [2.0.2] — 2026-11-08

### Исправлено
- Второй запуск клиента больше не создаёт вторую иконку в трее: он активирует уже
  запущенное окно (локальный сокет), а не показывает сообщение об ошибке.
- Updater после копирования проверяет, что клиент действительно запустился
  (лог `%TEMP%\MessengerUpdater.log` с кодом завершения), а клиент убирает иконку
  из трея перед выходом — «призрачные» иконки больше не остаются.

### Голос
- **Таймаут вызова 30 секунд**: вызывающий видит «Абонент не ответил», у
  вызываемого — «Пропущенный вызов от …».
- **Занято**: если вызываемый уже в звонке, он автоматически отклоняет вызов с
  причиной, вызывающий видит «Абонент уже в другом звонке». Сервер не даёт

- В карточке профиля (личный чат) появилась кнопка **«Позвонить»**.
- Отклонение вызова передаёт причину (`reason`) — `busy`, `timeout` или пусто.

## [2.0.1] — 2026-11-08

### Исправлено
- **После обновления клиент не перезапускался**: updater пытался заменить сам себя
  (`MessengerUpdater.exe` заблокирован) и завершался с ошибкой. Теперь он
  запускается из копии `MessengerUpdater.new.exe`, пишет лог
  `%TEMP%\MessengerUpdater.log`, показывает сообщение при ошибке и перезапускает
  клиент через `startDetached`, а при необходимости — через `ShellExecute`.
- Запуск updater из неустановленного клиента: если нужен UAC, используется
  `ShellExecute runas`.
- Для перехода **2.0.0 → 2.0.1** манифест не содержит `MessengerUpdater.exe`:
  иначе старый updater снова упёрся бы в собственный заблокированный файл.
  Новый updater попадёт при следующем обновлении или установке 2.0.1.

### Добавлено
- **Трей**: крестик сворачивает окно в трей, двойной клик открывает, в меню —
  «Открыть», «Проверить обновления», «Выход». Настройка «Сворачивать в трей при
  закрытии» (по умолчанию включена).
- **Автопроверка обновлений**: через 3 секунды после входа, затем каждые 6 часов
  и после переподключения; уведомление в трее о новой версии.

## [2.0.0] — 2026-11-08

### Безопасность голоса
- **UDP-звук шифруется AES-256-GCM** (OpenSSL EVP). Сервер — только релей и
  ключей не видит; ключ комнаты выдаётся по TLS в `voice.join` (`voice_key`).
- Защита от повторов: сервер и клиент отбрасывают пакеты с неподрастающим `seq`;
  nonce выводится из `seq`, подмена тега отклоняется.
- Jitter-буфер ключуется парой `(user_id, seq)` — несколько говорящих больше не
  конфликтуют по номерам пакетов.
- Новый формат UDP-пакета `MV02`; клиент и сервер нужно обновить вместе.

### Голос
- **Push-to-talk**: Настройки → Голос → «Push-to-talk», в шапке появляется
  кнопка «Говорить» (передача только при удержании).
- Выбор **микрофона и динамиков** в настройках; при недоступности — системные.

### Документация
- `docs/VOICE-SECURITY.md`: ключи, формат пакета, защита от повторов, ограничения.

### Тесты
- `tst_voice_crypto`: шифрование/расшифровка, подмена тега, чужой seq.
- `tst_voice_udp`: оба участника получают одинаковый ключ комнаты.
