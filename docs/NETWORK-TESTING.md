# Проверка на разных компьютерах и в разных сетях

## 1. Один компьютер (localhost)

1. Запустите **«Сервер MessengerApp»** из меню «Пуск» (или `MessengerServer.exe`).
   Окно консоли закрывать нельзя, пока работают клиенты.
2. Запустите **«MessengerApp»** (клиент).
3. В поле сервера оставьте `127.0.0.1`, порт `45000`.
4. Зарегистрируйте пользователя, затем запустите второй клиент с флагом
   `--profile second` и зарегистрируйте второго — они увидят общий чат.

## 2. Два компьютера в одной локальной сети

**На компьютере-сервере:**

1. Установите MessengerApp (установщик) или распакуйте портативную папку.
2. Запустите «Сервер MessengerApp». В окне консоли появится строка:

   ```
   Адрес в локальной сети:   192.168.1.42:45000
   ```

   Это адрес, который нужно ввести на клиентах.
3. Разрешите входящие подключения. Установщик добавляет правило брандмауэра для
   `MessengerServer.exe` (профили «частная сеть» и «домен»), если была отмечена
   галочка «Разрешить сервер в брандмауэре Windows». Если правило не создано,
   выполните в PowerShell **от имени администратора**:

   ```powershell
   netsh advfirewall firewall add rule name="MessengerApp Server" dir=in action=allow ^
       program="C:\Program Files\MessengerApp\MessengerServer.exe" enable=yes profile=private,domain
   ```

**На компьютере-клиенте:**

4. Запустите клиент, в поле сервера введите `192.168.1.42`, порт `45000`.
5. Зарегистрируйтесь или войдите. Оба компьютера должны быть в одной подсети.

**Проверка связи** (на клиенте, PowerShell):

```powershell
Test-NetConnection 192.168.1.42 -Port 45000
```

`TcpTestSucceeded : True` означает, что порт доступен.

## 3. Разные сети (через интернет)

Прямого шифрования в приложении нет (TLS вне объёма ТЗ), поэтому **не выставляйте
сервер напрямую в интернет без VPN**. Рабочие варианты:

**Вариант A — VPN (рекомендуется).** Поставьте Tailscale, ZeroTier или Radmin VPN
на оба компьютера, подключите их к одной виртуальной сети и используйте
VPN-адрес сервера (например, `100.64.0.5`) вместо локального.

**Вариант B — проброс порта.** На роутере сервера пробросьте TCP-порт `45000`
на его локальный IP, клиенты вводят публичный IP роутера. Учтите:

- трафик и пароли идут по сети **без шифрования**;
- сервер будет виден из интернета — используйте сложные пароли и не оставляйте
  его включённым без необходимости;
- провайдер может блокировать входящие подключения (CGNAT) — тогда остаётся VPN.

## 4. Смена порта

Сервер: `MessengerServer.exe --port 46000`.
Клиент: то же число в поле порта на экране входа (сохраняется в настройках профиля).

## 5. Если не подключается

| Симптом | Что проверить |
|---|---|
| «Нет соединения с сервером» | запущен ли сервер, совпадают ли IP и порт, не блокирует ли брандмауэр |
| `Test-NetConnection` возвращает `False` | правило брандмауэра, разные подсети, VPN |
| Порт занят при старте сервера | другой экземпляр сервера или программа на этом порту; смените `--port` |
| Подключение есть, но вход не проходит | логин/пароль, сервер смотрит в другую базу (`--data`) |
| Сообщения не доходят | сервер должен быть запущен всё время; при обрыве клиент переподключится сам |

## 6. Где лежат данные

- Windows: `%APPDATA%\MessengerApp\` (БД, вложения, логи, настройки).
- Профили клиента: `%APPDATA%\MessengerApp\profiles\<имя>\`.
- Переопределение: флаг `--data <каталог>` или переменная `MESSENGER_DATA_DIR`.

## 7. Ограничения

- Трафик не шифруется (TLS не входит в объём); используйте доверенную сеть или VPN.
- Групповые чаты — только общий чат и личные переписки.
- Видео воспроизводится, если в системе есть соответствующие кодеки; иначе плеер
  предложит открыть файл внешним приложением.
