# Автообновление и подпись издателя

Документ описывает механизм обновления: манифест, докачку изменённых файлов,
применение и подпись. Серверная и клиентская части реализованы в 1.8.0;
для подписи нужен сертификат УЦ.

## 1. Манифест

Сервер раздаёт каталог `updates/` (по умолчанию `<данные>/updates`,
переопределяется `--updates-dir`). В нём лежит `manifest.json`:

```json
{
  "version": "1.8.0",
  "files": [
    { "path": "MessengerClient.exe", "size": 1234567, "sha256": "…" },
    { "path": "libopus.dll", "size": 696913, "sha256": "…" },
    { "path": "translations/messenger_en.qm", "size": 4567, "sha256": "…" }
  ]
}
```

Правила:

- `path` — только относительный, без `..`, `\` и `:`;
- `size` и `sha256` обязательны;
- файлы лежат в `updates/` по тем же относительным путям;
- версия сравнивается с `MESSENGER_VERSION` клиента.

## 2. Проверка и докачка

1. Клиент запрашивает `update.manifest` по TLS (существующее соединение).
2. Считает sha256 локальных файлов из манифеста и сравнивает: в загрузку идут
   только отличающиеся. Размер загрузки = сумма размеров изменённых файлов.
3. Для каждого файла:
   - недокачанный файл лежит в `%TEMP%/MessengerUpdate/<version>/<path>.part`;
   - `update.download {path, offset}` — `offset` равен размеру `.part`;
   - сервер отдаёт файл с этого смещения чанками (64 КиБ), завершает `attach.end`;
   - клиент дописывает чанки, проверяет sha256 и переименовывает `.part`;
   - при обрыве связи повторный запуск продолжит с места остановки.
4. Если sha256 не совпал — файл удаляется и скачивается заново (один повтор).

Так скачиваются только изменённые файлы (пофайловая дельта), а не весь пакет.

## 3. Применение

Файлы программы заняты запущенным процессом, поэтому замена выполняется
отдельным `MessengerUpdater.exe`:

1. Клиент скачивает обновление в `pending/<version>/…` и пишет `pending/apply.json`.
2. Запускает updater (при установке в `Program Files` — с запросом UAC)
   и завершает работу.
3. Updater ждёт выхода клиента, копирует файлы поверх установки, удаляет `pending`,
   запускает `MessengerClient.exe` и закрывается.
4. При следующем старте клиент проверяет, что версия совпала, и убирает артефакты.

Откат: перед заменой updater сохраняет старые файлы в `backup/<version>/`;
если копирование не удалось — восстанавливает и показывает ошибку.

## 4. Подпись издателя (Authenticode)

Чтобы Windows показывала «проверенный издатель», нужен **сертификат подписи кода**
от доверенного УЦ (Sectigo, DigiCert, GlobalSign и т.п.). Самоподписанный
сертификат подписью «проверенного издателя» не станет — SmartScreen всё равно
предупредит; он годится только для внутренних тестов.

Подписываются:

- `MessengerClient.exe` и `MessengerUpdater.exe`;
- `MessengerServer.exe`;
- установщик `DiDog-Setup-*.exe` (Inno Setup поддерживает `SignTool`).

Скрипт `scripts/sign.ps1` (следующий этап) принимает PFX или отпечаток
сертификата из хранилища и вызывает `signtool sign /fd SHA256 /tr <timestamp>`.
В `build-installer.ps1` подпись вызывается после сборки, в `messengerapp.iss` —
`SignTool=...` для установщика.

Без сертификата сборка остаётся рабочей, но Windows покажет «Неизвестный издатель».

## 5. Что нужно от владельца

1. Купить сертификат подписи кода (или получить в УЦ организации).
2. Положить PFX и пароль в переменные окружения на сборочной машине
   (`MESSENGER_SIGN_PFX`, `MESSENGER_SIGN_PASSWORD`) или установить сертификат
   в хранилище и указать отпечаток.
3. Выкладывать в `updates/` новую версию: файлы + `manifest.json` с реальными
   sha256 (скрипт `scripts/make-manifest.ps1` — следующий этап).

## 6. Безопасность

- Манифест и файлы идут по TLS, но дополнительно проверяется sha256.
- Клиент принимает только файлы, перечисленные в манифесте; выход за каталог
  запрещён (проверяется на сервере и клиенте).
- Обновление применяется только к каталогу установки; путь установки берётся
  из расположения exe, а не из манифеста.
- Подпись издателя защищает от подмены установщика; для обновляемых файлов
  дополнительно можно проверять подпись перед заменой (после покупки сертификата).

## 7. Проверка подписи

Пайплайн проверен на тестовом самоподписанном сертификате:

```powershell
$env:MESSENGER_SIGN_PFX = "sign.pfx"
$env:MESSENGER_SIGN_PASSWORD = "…"
.\scripts\sign.ps1 -Files "dist\MessengerApp\*.exe" -TimestampUrl ""   # без сети
```

`Get-AuthenticodeSignature` показывает подпись, но статус `UnknownError` — это
ожидаемо для самоподписанного сертификата. После покупки сертификата УЦ тот же
скрипт даёт `Valid` и «проверенного издателя» в SmartScreen. Если сеть доступна,
уберите `-TimestampUrl ""`, чтобы добавить метку времени.

## 8. Выкладка обновления на сервер

1. Соберите Release и установщик (`scripts\build-installer.ps1` или
   `package-windows.ps1` + ISCC).
2. Сгенерируйте манифест **после** сборки:

   ```powershell
   .\scripts\make-manifest.ps1 -Version 2.0.0 -Dist dist\MessengerApp
   ```

   Получится `dist\MessengerApp\manifest.json` с версией, размерами и sha256.
   Для 2.0.0 готовый манифест также приложен к релизу (`manifest.json`).

3. Скопируйте содержимое `dist\MessengerApp` в каталог обновлений сервера
   (по умолчанию `/var/lib/messengerapp/updates`):

   ```bash
   rsync -av --delete dist/MessengerApp/ lostdead@51.250.76.250:/tmp/messenger-updates/
   ssh lostdead@51.250.76.250 'sudo rm -rf /var/lib/messengerapp/updates \
     && sudo mv /tmp/messenger-updates /var/lib/messengerapp/updates \
     && sudo chown -R messengerapp:messengerapp /var/lib/messengerapp/updates'
   ```

4. Перезапуск сервера не нужен: манифест читается при каждом `update.manifest`.
   Если служба запущена с `--updates-dir`, используйте этот каталог.

5. Проверьте обновление клиентом предыдущей версии: Настройки → Обновления →
   «Проверить обновления». Должны скачаться только изменённые файлы.
## 9. Скрипты 2.1.0

- `scripts/publish-update.ps1` — манифест, проверка хешей, tar.gz, scp и
  опциональная установка по SSH (`-Deploy -RemoteScript ...`).
- `scripts/deploy-update.sh` — распаковка, проверка хешей, staging, атомарная
  подмена каталога, откат при сбое; службу не перезапускает.
### Установщики с 2.5.0

- `DiDog-Client-Setup-<ver>.exe` — только клиент (рекомендуется всем).
  Не содержит `MessengerServer.exe`, поэтому не требует остановки службы.
- `DiDog-Setup-<ver>.exe` — клиент + локальный сервер + служба.
- `DiDog-Server-<ver>.zip` — серверный пакет для VPS/Windows-сервера.
