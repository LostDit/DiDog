# Безопасность голоса

С версии 2.0.0 голосовой UDP-трафик шифруется. Сервер остаётся релеем: он
пересылает зашифрованные пакеты, не имея возможности их расшифровать.

## Ключ комнаты

1. Первый участник вызывает `voice.join` — сервер создаёт для чата случайный
   ключ (32 байта) и кладёт его в память.
2. Ключ возвращается в ответе `voice.join` полем `voice_key` (hex) **по TLS**,
   вместе с `udp_port` и `udp_token`.
3. Следующие участники получают тот же ключ, пока комната не опустеет.
4. Когда последний участник выходит, ключ удаляется; следующая комната получит
   новый.

## Пакет

UDP-дейтаграмма (magic `MV02`):

```
uint32 magic | uint32 token(user) | uint32 seq | ciphertext | tag(16)
```

- `ciphertext||tag` — AES-256-GCM (OpenSSL EVP, libcrypto загружается динамически);
- nonce 12 байт — `seq` в big-endian с нулевым префиксом;
- заголовок не входит в AAD: сервер переписывает `user_id` при рассылке.

## Защита от повторов

- Сервер хранит `lastSequence` для каждого UDP-токена и отбрасывает пакеты,
  у которых `seq` не растёт; «привет» с пустым payload только обновляет адрес.
- Клиент хранит `lastSequence` для каждого отправителя и отбрасывает повторы и
  устаревшие пакеты до расшифровки.
- Пакет с неверным тегом или чужим seq не расшифровывается и отбрасывается.

## Буфер и несколько говорящих

Пакеты в jitter-буфере ключуются парой `(user_id, seq)`, поэтому голоса разных
участников не конфликтуют по номерам.

## Ограничения

- Это не end-to-end шифрование: сервер выдаёт ключи и теоретически может
  участвовать в комнате как клиент. Для E2EE нужен обмен ключами между
  участниками (будущая версия).
- Ключ живёт, пока в комнате есть хотя бы один участник; вышедший участник
  помнит ключ до перезапуска клиента. Ротация — при опустении комнаты.
- Голосовые данные не пишутся на диск.

## Push-to-talk и устройства

- **Настройки → Голос**: push-to-talk (микрофон передаёт только при удержании
  кнопки «Говорить» в шапке чата), выбор микрофона и динамиков.
- Устройства применяются при следующем звонке; при недоступности выбранного
  устройства используется системное.

## Вызовы

- Вызов ждёт ответа **30 секунд**; затем вызывающий видит «Абонент не ответил»,
  а вызываемый — «Пропущенный вызов».
- Если абонент уже в звонке, вызов автоматически отклоняется с причиной `busy`,
  вызывающий получает «Абонент уже в другом звонке».
- Сервер не разрешает одному клиенту состоять в двух голосовых комнатах.
- В карточке профиля личного чата есть кнопка «Позвонить».
## E2EE голоса (2.6.0)

Для **личных звонков** (два участника) медиаключ выводится на клиентах и
серверу неизвестен:

1. При входе в комнату клиент генерирует эфемерную пару **X25519**.
2. Публичный ключ отправляется через TLS: `voice.pubkey {chat_id, pubkey}`.
   Сервер пересылает его остальным участникам событием `ev.voice_pubkey`
   и хранит только до конца звонка.
3. Ответ `voice.join` содержит `participants` и `pubkeys` уже подключившихся.
4. Каждая сторона выводит общий секрет (`X25519`) и ключ
   `HKDF-SHA256(secret, "didog-voice", "chat-<id>")` — 32 байта для AES-256-GCM.
5. UDP-пакеты шифруются этим ключом; серверный ключ комнаты остаётся лишь
   запасным и для групп.

**Групповые звонки** (3+ участников) пока используют ключ комнаты, который
выдаёт сервер: полноценный E2EE для групп требует попарных ключей на каждого
отправителя и запланирован отдельным этапом. Признак: `participants > 2`.

Сервер по-прежнему видит только: кто с кем и когда говорит, размеры пакетов и
публичные ключи. Содержимое звука он расшифровать не может.
